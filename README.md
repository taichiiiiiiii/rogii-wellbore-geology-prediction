## 概要

モデリング自体は、フォークした公開ノートブックの系統に由来します。したがって本リポジトリで
読む価値があるのはモデルではなく**評価の仕組み**です。このコンペティションはあらゆる近道を
罰したため、何が信じられる証拠で何がそうでないかを判別する装置を作ることに労力の大半を
費やしました。以下はその記録です。

## 用語

記録の中で繰り返し使う語を先に定義します。

| 用語 | 意味 |
|---|---|
| ドロー | 1回の提出結果。同じコードでも提出ごとに public スコアは揺れる（標準偏差およそ 0.03）ため、1つのスコアは分布からの1標本にすぎない |
| ファミリー | 同一系統の設定群。ドローが揺れる以上、設定の優劣はファミリーの平均で比較する |
| ノブ | パイプライン内の調整可能な定数（シード数、混合比、多項式次数など） |
| プローブ | ノブを1つだけ変えた変種を提出し、その効果を測るための実験 |
| 検証環境（ハーネス） | 提出せずに手元で施策を評価する仕組み。本記録では train 坑井を使った疑似コンペティションを指す |
| 発火 | 条件付きの処理層が、実際にその条件を満たして動作すること |
| 事前登録 | 結果が届く前に採否の判定規則を台帳へ書き、後から動かさないこと |

## 課題とデータ

水平坑井には測定深度に沿った1次元のガンマ線（GR）ログがあり、垂直の*タイプウェル*には
層序深度（TVT、True Vertical Thickness）に対する GR の特徴があります。水平坑井のログは
タイプウェルのログを局所的にずらして伸縮させた複製なので、TVT の予測とは各横方向位置で
ドリルビットが層序のどこにいるかを突き止めることです。

この課題の性質は、コンペティション期間中に別の参加者（malyshevdanil 氏）が公開した
Working Note『The Wiggle Is Free, the Trend Is the Wall』で明快に示されました。以下の3点は
同氏の分析によるもので、当方は自分たちの坑井データで再確認したうえで前提として採用して
います。

1. **課題は厳密に分解でき、誤差は1本の滑らかなトレンドだけに宿ります。**
   `TVT = surface − Z` であり、`Z` は評価区間で厳密に既知なので高周波成分は無償です。真の
   surface は測定深度の2次多項式で R² = 0.9925 まで説明できます。手元の10坑井で再計算すると
   1次で 6.356、2次で 3.332、3次で 2.711 となり、同氏の結果と整合しました。
2. **そのトレンドは GR から復元できません。** サブサイスミック断層（地震探査では捉えられない
   微小な断層）は GR に符号化されていません。同氏が試した 22 通りのニューラルネットワーク
   構成はいずれも RMSE 11 付近で頭打ちになりました。当方が独立に作った4つの学習モデルも
   最良で 9.6 にとどまり、同じ壁を別経路で再現した形です。
3. **適用先を判定できない信号には価値がありません。** 当方は5つの経路で「信号は確かにある」
   ことを示せましたが、「どこに適用すべきか」は最後まで示せませんでした。上位陣が非公開で
   持っていたのは、より良いモデルではなくこの判定機構だと考えています。

同じ指標で測った代表点（RMSE、単位は ft、小さいほど良い）:

| 参照点 | RMSE |
|---|---|
| 滑らかな surface を厳密に知るオラクル | 3.90 |
| コンペ終盤の public LB 首位 | 4.68 |
| **本提出** | **6.39** |
| 線形オラクル | 6.60 |
| 単体のパーティクルフィルタ、または最良のニューラルネットワーク | 約 11 |
| 定数予測 | 15.91 |

## 手法

### パイプラインの系譜

最終提出は「Contact-Gated Stratigraphic Alignment」と通称される公開ノートブックの系統に
属します。源流は blacklions 氏の投稿で、そこから複数の作者を経て、フォーク元である
evgendvorkin 氏の版に至ります。単一ノートブック・インターネット遮断・9時間制限という
コードコンペティションの制約下で動き、7本の外部データセットをマウントします。実際に参照
されているのは次の4本で、残り3本はコードから参照されていませんでした。

- 学習基盤ライブラリ（オフライン依存パッケージ）
- 事前計算特徴テーブルと、事前学習済みの LGBM 3本・CatBoost 2本
- 学習軌道を出すための事前学習済み booster
- ドリフト補正モデル

### 7段階の処理

**Stage 1 — アンカーの生成。** 2つの独立した推定器を作ります。1つは事前学習済み GBDT 群
（195 特徴）をリッジ回帰でスタックした残差アンサンブル。もう1つは 128 シードの尤度重み付き
パーティクルフィルタで、状態を（層序位置・変化率）とし、観測尤度を
`exp(−0.5·((GR − G_typewell(T)) / gs)²)` で与えます。この `gs` がフィルタの許容幅を決める
主要なノブです。さらに selector が、坑井の形状（評価行数や Z 方向の広がり）に応じて
パーティクルフィルタの設定を選び分けます。両者を `T_A = 0.30·T_ridge + 0.70·T_selector` で
合成します。

**Stage 2 — 層序レベルでの平滑化。** 含意層序レベル `U = T + Z` を正規化 MD 空間の
ロバスト多項式で平滑化し、`T_proj = (1−λ_p)·T_A + λ_p·(Û − Z)` として戻します（λ_p = 0.75）。
課題の性質1（誤差は滑らかなトレンドに宿る）を直接利用する段で、**最終的に採用した変更の
1つはここの多項式次数を3から2へ下げるものです。**

**Stage 3 — 学習軌道とのブレンド。** 事前学習済み booster による軌道 `T_learned` と
`T_blend = 0.60·T_proj + 0.40·T_learned` で混ぜます。

**Stage 4 — 同一坑井のコンタクト上書き。** テスト坑井の ID が train に存在する場合に限り、
地層コンタクトから TVT を再構成し、可視プレフィックスの RMSE が 1.0 ft 未満という自己検証を
通った坑井だけを上書きします。ただし**隠しテストでは一度も発火しません**（隠し坑井の ID は
すべて新規）。可視3坑井では 3/3 発火するため、可視スコアの見かけだけを作る層です。この
非対称性が、後述する検証規律の出発点になりました。

**Stage 5 — 可視プレフィックス校正。** この系統の核心なので節を改めて説明します。

**Stage 6 — ドリフト補正。** 別モデルによる補正をゲート付きで加えます。重みの上限は
0.00425 で、予測どうしの食い違いが大きい場合は自動的に無効化されます。したがって移動量は
小さく抑えられます。

**Stage 7 — シードブランチのヘッジ。** パーティクルフィルタの事後分布が二峰になった坑井に
対し、両峰の中点方向へ最大 2.0 ft シフトします。**採用したもう1つの変更（シード数を 128 から
192 へ）は、この段の発火条件を変えることで予測を動かします。**

### Stage 5 の詳細 — 可視プレフィックス校正

評価区間の予測は正解と突き合わせられませんが、その手前の既知区間（プレフィックス）は正解が
分かっています。そこで**既知区間の末尾を意図的に隠して評価区間の代わりに使い**、複数の候補
生成器をその上でランキングして最終軌道を選びます。坑井ごとに、その坑井自身のデータだけで
生成器を選べる点が要です。

| パラメータ | 値 | 役割 |
|---|---|---|
| 切り出し比 | 0.50 / 0.65 / 0.75 | 既知区間のどこまでを「既知」として残すか。3通りで評価して平均する |
| 校正シード数 | 24 | ランキング時のパーティクルフィルタのシード数 |
| 最終シード数 | 48 | 選ばれた生成器で最終軌道を出すときのシード数 |
| 粒子数 | 350 | 校正・最終とも共通 |
| α 乗数 | 1.30 | ヒール部の GR に掛けるアフィン較正の強さ |
| プロファイル | balanced | 候補生成器の集合と選択規則のプリセット |

プロファイルには conservative / balanced / aggressive の3種があり、**この選択は本記録で最も
教訓的な失敗の1つです。** 手元の検証環境では conservative が balanced より 0.28 良いという
結果が出ていました。ところが実際に提出すると **7.235**、当時の主力（6.4 台）から 0.8 以上の
悪化でした。検証環境が劣化構成だったために順位が逆転していたのです。以後、プロファイルは
実測が支持する balanced で凍結しました。

この段には構造的な難しさもあります。プレフィックスは坑井の「かかと」側に偏っており、評価
区間は「つま先」側です。プレフィックスで良い生成器が評価区間でも良い保証はなく、そこを
埋める手段は最後まで見つかりませんでした。課題の性質3（信号はあるが適用先を判定できない）が
最も直接的に現れる場所です。

### 自前で試して届かなかった手法

レジストレーションを直接学習させる方向も4回試しました。BiGRU、タイプウェルへのクロス
アテンションを載せた TCN、seq2seq、ドナー坑井を使った回帰の4件です。最良で RMSE 9.6、
それ以外は 14 から 15 の水準にとどまりました。原因は課題の性質2（トレンドが GR に符号化
されていない）にあり、アーキテクチャの選択では超えられません。設計文書は `docs/` と
`analysis/seq2seq_design.md` に残しています。

### 加えた変更

最終的にスコアへ効かせた変更は定数2つです。加えて、上流の安全装置を緩めた変更が1つあります
（参照提出の SHA を固定して例外を送出する監査があり、予測を変える設定変更はすべて引っかかる
ため、例外送出を表示に変えました。同じセル内の構造的な検証は残しています）。さらに可搬性の
修正が2つあります。Kaggle の入力マウント構成は2種類あり、上流は片方のパスをハードコード
しています。旧構成に当たると、実行がその場で止まるか、**エラーを出さないままリッジ資産だけが
欠落**します。詳細は `main` ブランチを参照してください。

## 検証戦略

評価は **40 坑井を単位とした交差検証**（train から抽出した坑井を fold に分け、fold 外の
坑井でのみ評価する）で行いました。坑井単位で分割するのは、同一坑井の行が train と評価に
またがると予測が自明になるためです。

**採用した原則は「in-sample の値は採用の根拠にしない」です。** これは4回痛い目を見た結果
決めたものです。交差検証は、当てはめの段階で魅力的に見えた値を次のように覆しました
（いずれも RMSE の変化量、単位 ft、負が改善・正が悪化）。

| 試した変更 | 当てはめ値 | 交差検証（40 坑井） |
|---|---|---|
| 軌道特徴 | −0.274 | +0.566 |
| 空間 surface | −0.093 | +0.024 |
| 内挿物理 | −0.337 | +1.399 |
| surface 後処理 | −0.15 | +0.035 |

最後の1件は提出の数時間前に撤回しました。原因は数値で説明できます。**最悪 5% の坑井が
二乗誤差の 52.5% を占める**ため、40 坑井規模の当てはめは系統的に誤導します。

## 効いたこと

正直に書くと、スコアを動かした変更はほとんどありません。最終的に採用したのは、トレンド
当てはめの次数を3から2に下げる変更（オフライン評価とリーダーボードの両方から独立に支持
された唯一の変更で、真の surface が2次であるという測定とも一致）と、パーティクルフィルタの
シード数を増やす変更の2件だけです。

一方で、**手法として効いたのは事前登録**です。判定規則を結果が出る前に台帳へ書き、機械的に
執行しました。後述の罠は、この規律がなければすべて実損になっていました。

## 効かなかったこと

こちらが本題です。それぞれ、なぜ効かなかったかを機序まで特定しました。

**Leave-one-site-out 検証とリーク監査を通しても十分ではありません。** レベリング施策
（R114–R130）は6ブロックの leave-one-site-out で Δ −1.08 を示し、変異試験によるリーク検査も
199,746 行で差分ゼロでした。しかし未接触の坑井群に対して測り直すと **−0.069** まで縮み、
事前登録した棄却規則が発火して提出を中止しました。なおプラセボ対照は2種類用意しましたが、
このうち符号反転プラセボは検証設計上ほとんど情報を持たないことが後から判明し、有効だったのは
坑井ラベルの並べ替えによる対照だけでした。**完璧に見える証拠の束が、未接触のドロー1点に
負けます。**

**事前学習済み資産を含む検証環境は、一様にではなく選択的に壊れます**（R140–R142）。疑似
コンペティション形式の検証環境は、あるノブを Δ −0.373・10 坑井中8坑井改善と評価しました。
本プロジェクトで観測した中で最も強い信号です。ところがリーダーボードでは **+0.17** と明確に
悪化しました。ブレンド成分を連立方程式で復元して理由が判明します。**リッジ資産が検証環境の
坑井を記憶しており**（成分単体の RMSE は 3.93、対になる成分は 5.82）、検証環境は「記憶して
いる成分の重み」を高く評価していました。同じ検証環境は、その資産に触れないノブについては
リーダーボードと一致していました。対照アームと事前登録規則のおかげで、この罠に賭けずに
済んでいます。

**ビット同一のコードでもスコアは一致しません。** 可視出力の SHA-256 が一致する2つの
ノートブックが、隠し再実行で 6.470 と 6.500 に分かれました。可視実行で観測した決定性は採点
経路に外挿できず、ドローのノイズは約 0.03 です。したがって設定の比較はファミリー平均で
行うべきで、最良ドローで行ってはいけません。

**公開ノートブックのタイトルの数字は、保存されたコードから再現しません。** 保存コードを実行
したところ、4件でタイトルと実測が食い違いました。**食い違いは両方向に出ます。** タイトルが
古くて実測の方が良い例（7.872 と題されたノートブックが 6.361）もあれば、実測の方が悪い例
（6.390 と題されたノートブックが 6.515）もあります。作者はスコアを名前に固定したまま更新を
続けるため、**保存されているコードは命名時点のコードではない**と考えるのが安全です。

## 最終提出の選択

最終順位は選択した2件のうち良い方で決まります。したがって組の**期待スコア**は「平均 −
ヘッジ」で表せます（RMSE なので小さいほど良い）。ヘッジは2件の外し方が違うほど大きくなり、
期待スコアを押し下げます。候補10組すべてについて両方の項を実測しました。

数週間主力にしていたファミリーは平均 6.5195（n = 13）、最終的に採用したファミリーは
6.4049（n = 7）で、前者は 0.115 劣ります。両者の実測ばらつき（標準偏差 0.058 と 0.017）から
計算すると、前者のドローが後者のドローより良くなる確率は約 3% でした。したがって最終選択から
完全に除外しました。

選んだ組が1位になったのは平均が最も低いためで、2件の食い違いの大きさ自体は次点の組の方が
わずかに上回っています。**この組のヘッジは主に片方（次数を下げた変種）が担っており**、もう
片方は基準設定との誤差相関が 0.998 と高く、単独ではヘッジになりません。実際、最良ドローを
基準設定と組ませる選択はヘッジの観点で10組中最下位でした。

上位3組の差は 0.01 程度でノイズの範囲内です。唯一確かな判断は、平均が 0.115 劣る系統を外す
ことでした。

  （作者: **evgendvorkin**）も含まれます。いずれもオープンソースライセンスの表示がないため、
  Git の追跡対象から外しました。`main` はパッチのみを公開し、上流はビルド時に Kaggle から
  取得します。
