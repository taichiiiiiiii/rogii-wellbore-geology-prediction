## 背景

水平坑井には測定深度に沿った1次元のガンマ線（GR）ログがあり、垂直の*タイプウェル*には
層序深度（TVT、True Vertical Thickness）に対する GR の特徴があります。地下は成層している
ため、水平坑井の GR はタイプウェルの GR を局所的にずらして伸縮させた複製になっています。
TVT を予測するとは、各横方向位置でドリルビットが層序のどこにいるかを突き止めることであり、
地質学的な事前分布を伴う信号レジストレーション問題です。

この課題の性質は、コンペティション期間中に別の参加者
（[malyshevdanil 氏の Working Note](https://www.kaggle.com/competitions/rogii-wellbore-geology-prediction/discussion)）
が公開した分析で明快に示されました。私たちはそれを自分たちのデータで再確認したうえで、
以下を前提に動いています。

1. **課題は厳密に分解でき、誤差は1本の滑らかなトレンドだけに宿ります。**
   `TVT = surface − Z` であり、`Z` は評価区間で厳密に既知なので、高周波成分は無償で
   手に入ります。真の surface は測定深度の2次多項式で R² = 0.9925 まで説明できます。
2. **そのトレンドは GR から復元できません。** サブサイスミック断層（地震探査では捉えられない
   微小な断層）は GR に符号化されていません。同氏が試した 22 通りのニューラルネットワーク
   構成はいずれも RMSE 11 付近で頭打ちになり、私たちが独立に作った4つの学習モデルも、
   最良で 9.6 と同じ壁の手前で止まりました。
3. **適用先を判定できない信号には価値がありません。** 私たちは5つの経路で「信号は確かに
   ある」ことを示せましたが、「どこに適用すべきか」は最後まで示せませんでした。上位陣が
   非公開で持っていたのは、より良いモデルではなくこの判定機構だと考えています。

参考として、同じ指標で測った代表点を挙げます（RMSE、単位は ft、小さいほど良い）。

| 参照点 | RMSE |
|---|---|
| 滑らかな surface を厳密に知るオラクル | 3.90 |
| コンペ終盤の public LB 首位 | 4.68 |
| **本提出** | **6.39** |
| 線形オラクル | 6.60 |
| 単体のパーティクルフィルタ、または最良のニューラルネットワーク | 約 11 |
| 定数予測 | 15.91 |

11 と 6.39 の差はモデルの表現力ではなく、公開ノートブックの系統が既に築いていた物理由来の
パイプラインによるものです。

## インストール

Kaggle アカウントと API トークンが必要です。トークンは Kaggle の Account ページから
`kaggle.json` を取得し、`~/.kaggle/kaggle.json` に配置してパーミッションを `600` にして
ください。

```bash
pip install kaggle
```

`build_final_submissions.py` は Python 3.11 以上で動き、標準ライブラリのみを使います。

## 使い方

上流ノートブックを取得し、パッチを適用して2つのノートブックを生成します。

```bash
kaggle kernels pull evgendvorkin/rogii-physics-lb-7-872-v48 -p upstream -m
python build_final_submissions.py upstream/rogii-physics-lb-7-872-v48.ipynb -o build
```

生成された `kernel-metadata.json` の `id` の先頭（`YOUR_KAGGLE_USERNAME`）をご自身の Kaggle
ユーザー名へ書き換えてから、`kaggle kernels push -p build/rogii-v2-projdeg2-probe` のように
実行してください。

各編集は完全一致する固有の文字列を目印にしており、目印が見つからない場合や複数箇所に一致
する場合は実行を中止します。上流が更新されたときに、それらしく見えるだけの別物へ黙って
パッチが当たることを防ぐためです。

> **バージョン固定について。** `kaggle kernels pull` は常に最新版を取得します。作者は本稿
> 執筆時点までに 85 版を重ねているため、**現在の最新版に対して同じパッチを当てても、私たちが
> 提出したものと同一にはなりません**。私たちが 2026-08-03 に取得した版に対しては、生成物が
> 実際に提出・採点されたノートブックと SHA-256 まで一致することを確認しています。

提出状況と最終選択の検証には次を使います。

```bash
python scripts/submission_status.py                  # カーネル別に提出をまとめて表示
python scripts/submission_status.py --final-check    # 最終選択が計画と一致するか検証
```

最終選択は Kaggle の Web UI からしか設定できません。API（`SUBMISSION_GROUP_SELECTED`）から
読み戻すこのチェックが、選択が実際に反映されたことを確かめる唯一の客観的な手段です。

## 編集の中身

編集は4種類あり、カーネルごとに4箇所または8箇所へ展開されます。うち3種類は両カーネル共通で、
残りが実験本体です。

**共通1・2: 入力パスの実行時解決。** Kaggle は入力を2種類のディレクトリ構成でマウントし、
どちらが割り当てられるかは事前に分かりませんが、上流ノートブックは片方のパスをハードコード
しています。旧構成に当たった場合、コンペデータの定数は最初のデータ読み込みで実行を止め、
リッジ資産の定数は `.exists()` ガードの内側にあるため**エラーを出さないままモデル成分だけが
欠落**します。実行時に解決すれば現行構成では挙動が変わらず、旧構成だけが修復されます。これを
突き止めるまでにカーネルの実行を7回無駄にしました。

**共通3: 上流の監査の緩和。** 上流には参照提出の SHA を固定し、不一致なら例外を送出する監査
セルがあります。予測を変える設定変更はすべてこれに引っかかります。緩和したのは例外送出を
表示に変えた1箇所だけで、同じセル内の構造的な検証はすべて残しています。

**実験本体: 定数1つ（カーネルごとに異なる）。** `projdeg2` はトレンド当てはめの次数を3から
2へ下げます。オフライン評価とリーダーボードの両方から独立に支持された唯一の変更で、真の
surface が2次であるという測定とも一致します。`seeds192` はパーティクルフィルタのシード数を
増やします。

`seeds192` については副作用があり、これが8箇所へ展開される理由です。シード数を増やすと事後
分布が変わり、上流のシードブランチ・ヘッジが発火しなくなります。その結果、同じセル内の
後続の検証3箇所も引っかかるため、あわせて緩和しています。**この経路では、上流が特定の1坑井に
対して加えている固定オフセット（+0.522 ft）が適用されません。** シード数の変更だけでは説明
できない差が予測に生じるのはこのためです。

## 最終2件の選び方

最終順位は選択した2件のうち良い方で決まります。したがって組の**期待スコア**は「平均 −
ヘッジ」で表せます（RMSE なので小さいほど良い）。ヘッジは2件の外し方が違うほど大きくなり、
期待スコアを押し下げます。public スコアの良い順に機械的に選ぶのではなく、両方の項を実測
しました。

なお以下では、同一の設定でも提出ごとに public スコアが揺れる（標準偏差およそ 0.03）ことを
踏まえ、**1回の提出結果を「ドロー」、同一系統の設定群を「ファミリー」**と呼びます。

- **平均**: 最終的に採用したファミリーの public ドローは 6.389〜6.442（n = 7、標準偏差
  0.017）に集中します。数週間主力にしていた別のファミリーは平均 6.5195（n = 13）で 0.115
  劣ります。両者のばらつきから計算すると、後者のドローが前者のドローより良くなる確率は
  約 3% でした。よって**最終選択から完全に除外しました**（そのファミリーの最良ドローは
  6.411 でした）。
- **ヘッジ**: 候補10組すべてを期待スコアで比較した結果、`projdeg2 + seeds192` が最良でした。
  ただしこの組が1位になったのは平均が最も低いためで、2件の食い違いの大きさ自体は次点の組の
  方がわずかに上回っています。**この組のヘッジは主に `projdeg2` が担っています**
  （`seeds192` は基準設定との誤差相関が 0.998 と高く、単独ではヘッジになりません）。
  実際、最良ドローを基準設定と組ませる選択はヘッジの観点で10組中最下位でした。

上位3組の差は 0.01 程度でノイズの範囲内です。唯一確かな結論は、ファミリー平均が 0.115 劣る
系統を外すことでした。
